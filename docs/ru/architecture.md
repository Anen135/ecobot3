# Архитектура

## Обзор

Проект построен вокруг **главного игрового цикла** в `main.py` и пакета `engine`, в
котором каждая подсистема живёт в собственном модуле:

* `settings.py` — единая точка загрузки конфигурации;
* `world.py` — контейнер сущностей и правила мира;
* `entity.py` — модель сущности и её реестр;
* `control.py` — контроллеры (управление сущностями);
* `camera.py` — виртуальная камера с `offset`;
* `ui.py` — отрисовка сетки и отладочной панели;
* `utils.py` — вспомогательные классы (`Timer`, `StepCounter`).

Зависимости модулей:

```
main.py
  ├── engine.ui        (draw_grid, draw_debug_panel)
  ├── engine.settings  (константы конфигурации)
  ├── engine.world     (World)
  ├── engine.entity    (ENTITY_REGISTRY, load_world_objects, Agent)
  ├── engine.camera    (Camera)
  └── engine.control   (контроллеры)

engine.world    ──> engine.settings, engine.entity
engine.entity   ──> pygame
engine.camera   ──> engine.settings
engine.ui       ──> engine.settings
engine.control  ──> pygame
engine.settings ──> config/*.json
```

Пакет `engine` не имеет внешних зависимостей, кроме `pygame` и стандартной библиотеки
(`json`, `math`, `os`).

## Главный цикл (`main.py`)

Последовательность инициализации:

1. `pygame.init()` и создание окна (размер/полноэкранность берутся из конфигурации).
2. Создание пустого `World()`.
3. Загрузка объектов из `config/world_objects.json` через `load_world_objects()` и
   добавление их в мир с помощью `world.add_entity()`.
4. Создание агента из `config/agent_config.json` (координаты появления, размер, цвет, угол) с
   контроллером, выбранным через `create_controller()` — и добавление его в мир.
5. Создание камеры — `Camera(world, target=agent)` (режим берётся из конфигурации).

Главный цикл по кадрам:

```
dt = (clock.tick(FPS) / 1000.0) * TIMESCALE     # дельта времени в секундах
process events (QUIT / ESC)                      # → выход из цикла
world.update(dt)                                 # update() каждой сущности + правила мира
camera.update()                                  # пересчёт смещения камеры
screen.fill(BACKGROUND_COLOR)
ui.draw_grid(screen, camera.offset)              # прокручиваемая сетка
world.draw(screen, camera.offset)                # отрисовка сущностей, отсортированных по слоям
ui.draw_debug_panel(screen, agent, dt, world, clock)  # только если DEBUG
pygame.display.flip()
```

**Важно:** `dt` — это время, прошедшее с предыдущего кадра (в секундах), умноженное на
`TIMESCALE` из конфигурации. Всё движение сущностей должно масштабироваться на `dt`, чтобы
скорость не зависела от FPS.

## Слои отрисовки

Порядок отрисовки определяется полем `layer` сущности. В `World.draw()` сущности
сортируются по возрастанию `layer`:

| Значение `layer` | Назначение |
| --- | --- |
| `-1` | фон |
| `0` | объекты (по умолчанию для `Food`, `Obstacle`, `Agent`) |
| `1+` | эффекты |

У сущностей есть **две системы координат**:

* мировые координаты `(x, y)` — физическая позиция сущности;
* экранные координаты — `(x, y) - camera_offset`, вычисляются при отрисовке.

Камера устанавливает `offset` так, чтобы целевая сущность оказалась в центре экрана.

## Мир и правила мира

`World` (`engine/world.py`) хранит список `entities` и применяет правила в зависимости от `world.type`:

* **`infinite`** — никаких ограничений; `apply_world_rules()` сразу возвращается;
* **`bounded`** — координаты сущностей ограничиваются границами мира, отрисовывается граница мира;
* **`torus`** — координаты берутся по модулю размера мира; сущности отрисовываются с
  дубликатами по краям через `get_wrapped_positions()`.

`World.update(dt)` вызывает `entity.update(dt)` для каждой сущности, затем `apply_world_rules(entity)`,
а в конце — `handle_collisions()`.

## Система сущностей

Базовый класс `Entity` (`engine/entity.py`) хранит: координаты, `layer`, `size`, `color`,
`tags` (множество строковых меток) и флаг `is_alive`.

Подклассы:

* `Food` — красная еда, тег `"food"`;
* `Obstacle` — прямоугольное препятствие (`width` / `height`), тег `"obstacle"`;
* `Agent` — имеет `controller` и `angle` (направление в градусах, 0 = вправо); `update()`
  делегирует управление контроллеру; рисует жёлтую линию направления.

Типы регистрируются в `ENTITY_REGISTRY = {"agent": Agent, "food": Food, "obstacle": Obstacle}`.
Загрузка объектов из JSON (`load_world_objects`) использует этот реестр: поле `"type"` в JSON
определяет класс; остальные поля передаются конструктору как именованные аргументы
(поле `"type"` при этом удаляется из параметров).

## Контроллеры

Интерфейс `Controller.update(entity, dt)` — сущность вызывает собственный контроллер изнутри
своего `update()`. Реализации:

| Контроллер | Управление |
| --- | --- |
| `KeyboardController` | WASD — движение по осям X/Y, скорость в px/s |
| `RotatingController` | Q/E — поворот, W/S — вперёд/назад вдоль `angle` |
| `MouseController` | поворачивается и движется к курсору (как ослик за морковкой) |
| `AIAgentController(world, ...)` | движется к ближайшей еде (ищется по тегу `"food"`) |

Контроллер игрового агента выбирается в `config/agent_config.json` по имени. Имена регистрируются
в `CONTROLLER_REGISTRY`; `create_controller()` создаёт экземпляр (передавая ссылки на `world` и
`camera` контроллерам, которым они нужны).

## Камера

`Camera` (`engine/camera.py`) вычисляет `offset` в зависимости от `camera.mode`:

* **`fixed`** — фиксированное смещение `fixed_pos` (0, 0);
* **`follow_agent`** — следует за `target` (обычно за агентом), центрируя его;
* **`follow_food`** — следует за едой, ближайшей к цели.

Для миров `bounded` смещение ограничивается границами мира, чтобы вид никуда не выходил за карту.

## Система коллизий

Реализована в соответствии с [collision_system.md](collision_system.md):

* `entity.on_collision(other, world)` — реакция на столкновение; каждый объект сам решает,
  как себя вести (Food — исчезает при попадании агента, Obstacle — отменяет движение другого);
* флаг `blocks_movement` — блокирует ли объект движение (`True` для `Obstacle`);
* `World.handle_collisions()` — проверяет пары через `colliderect()` и вызывает `on_collision()` с
  обеих сторон; вызывается из `World.update(dt)` после движения; мёртвые сущности удаляются.

Опциональные расширения (круговые коллизии, коллизии по слоям/маскам, события выхода) остаются открытыми.
