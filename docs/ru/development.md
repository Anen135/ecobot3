# Руководство разработчика

## Окружение

Проект рассчитан на **Python 3.10+** (используются выражения `:=` и аннотации типов).

Единственная внешняя зависимость — **Pygame**:

```
pip install pygame
```

В репозитории есть локальная папка `venv/` (не коммитится). Запуск с её помощью:

```
venv\Scripts\python.exe main.py      # Windows / PowerShell
```

## Запуск

```
python main.py
```

Управление (по умолчанию используется `RotatingController`):

| Клавиша | Действие |
| --- | --- |
| `Q` / `E` | Поворот против часовой / по часовой стрелке |
| `W` / `S` | Движение вперёд / назад вдоль текущего направления |
| `ESC` | Выход |

## Линтинг

`pyproject.toml` настраивает [ruff](https://docs.astral.sh/ruff/) (игнорируются `E701`, `I001`).
Запускайте перед коммитом:

```
ruff check .
```

## Соглашения

* Комментарии в коде и docstring пишутся на **русском** (соглашение проекта); документация
  в `docs/` ведётся **на английском**.
* Скорости задаются в пикселях в секунду; всё движение умножается на `dt`.
* Поле `layer`: `-1` — фон, `0` — объекты, `1+` — эффекты.
* Новые типы сущностей регистрируются в `ENTITY_REGISTRY` — после этого их можно загружать из JSON.
* Не используйте пустой `pass` внутри `apply_world_rules` (сейчас `return`, чтобы sourcery не ругался).
* Отладочный вывод и панели скрываются за флагом `DEBUG` из конфигурации.

## Известные проблемы и замечания

1. **`AIAgentController._find_closest_food()`** обращается к `e.type`, но у сущностей нет поля
   `type` (у них есть `tags`). Использование этого контроллера вызывает `AttributeError`. По
   умолчанию в `main.py` используется `RotatingController`, поэтому баг не проявляется. Исправление:
   фильтровать по тегам, например `"food" in e.tags` (как в `tags={"food"}`).

2. **Поиск еды по цвету** — `Camera._find_nearest_food()` ищет еду как
   `e.color == (255, 0, 0)`. Это хак с угадыванием цвета: если цвет еды изменится
   (в конструкторе или JSON), камера перестанет её находить. Лучше фильтровать по тегам, как в пункте 1.

3. **Объекты мира загружаются не через `settings`** — `main.py` жёстко прописывает
   `"config/world_objects.json"`, хотя в `engine_config.json` уже есть привязка `"objects"`.
   Загрузка объектов через `load_named_config("objects")` унифицировала бы конфигурацию.

4. **Нет файла зависимостей** — отсутствуют `requirements.txt` / секция зависимостей в
   `pyproject.toml`, поэтому зависимость от Pygame нигде не зафиксирована.

5. **Расширения коллизий не реализованы** — базовая система (`on_collision` /
   `blocks_movement` / `handle_collisions`) реализована в соответствии с
   [collision_system.md](collision_system.md); опциональные расширения (круговые коллизии,
   коллизии по слоям/маскам, события выхода) остаются открытыми.

## Рабочий процесс

* Основная ветка — `main`. История коммитов ведётся на русском.
* Обновляйте `docs/` синхронно с кодом.
