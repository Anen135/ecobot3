# Система коллизий — спецификация

> Статус: **реализовано**.
> Этот документ дублирует техническое задание из [TODO.md](../../TODO.md) и служит
> внутренним справочником для реализации.

## 🎯 Цель

Реализовать расширяемую систему коллизий, в которой любой игровой объект может:

* участвовать в столкновениях;
* по-разному реагировать на столкновение в зависимости от своего типа;
* блокировать движение или нет;
* взаимодействовать выборочно (например, агент с едой, но не с фоном).

---

## 🧱 Основные компоненты

### 1. Столкновение — объекты пересекаются

* Объекты проверяются на пересечение своих физических форм (по умолчанию — прямоугольник `Rect`).
* Форма задаётся методом `get_rect()`, который возвращает `pygame.Rect`.
* `get_rect()` уже реализован для `Entity`, `Obstacle` (и наследуется `Food`, `Agent`).

### 2. Участие в столкновениях

* **Все сущности** участвуют в проверке коллизий.
* Исключение: визуальные или неинтерактивные эффекты — их можно исключить через логику (`skip_collision_check()`).

### 3. Реакция на столкновение — через `on_collision(other, world)`

Каждый объект реализует собственную логику реакции на столкновение:

```python
def on_collision(self, other: Entity, world: World):
    pass
```

* Объект **сам решает**, что делать при столкновении с другим.
* Примеры:

  * 🍎 **Еда**: исчезает при попадании агента.
  * 🧱 **Препятствие**: отменяет движение агента.
  * ☠️ **Враг**: наносит урон.
  * 🌀 **Зона**: меняет состояние агента.
  * 🌟 **Эффект**: игнорирует столкновение (пустая реализация).

### 4. Флаг `blocks_movement`

* Отдельный флаг (`True`/`False`), определяющий, блокирует ли объект движение.
* Может использоваться для отмены движения:

```python
if other.blocks_movement:
    entity.revert_position()
```

> Примечание: `revert_position()` реализован в `Entity` — он восстанавливает `x`/`y` до позиции,
> сохранённой методом `save_position()` в начале кадра.

### 5. Обработка коллизий в `World`

* Метод `handle_collisions()`:

  * перебирает все пары объектов;
  * проверяет `colliderect`;
  * вызывает `on_collision()` с обеих сторон:

```python
entity.on_collision(other, self)
other.on_collision(entity, self)
```

## 🧪 Примеры поведения

#### 🍎 Еда

```python
class Food(Entity):
    def on_collision(self, other, world):
        if isinstance(other, Agent):
            other.score += 1
            world.entities.remove(self)
```

#### 🧱 Препятствие

```python
class Obstacle(Entity):
    blocks_movement = True

    def on_collision(self, other, world):
        if hasattr(other, 'revert_position'):
            other.revert_position()
```

#### ☠️ Враг

```python
class Enemy(Entity):
    def on_collision(self, other, world):
        if isinstance(other, Agent):
            other.health -= 10
```

## 🔍 Расширения (опционально)

* ✅ Круговые коллизии (`circle_radius`, `distance_to`)
* ✅ Коллизии на основе слоёв (`collision_layer`) и масок (`collides_with`)
* ✅ Управление приоритетом обработки
* ✅ События выхода (например, `on_exit_collision()`)

---

## 📌 Требования

* Коллизии поддерживаются между всеми активными объектами.
* Реакция задаётся через метод `on_collision()`, без завязки по типам.
* Должна быть возможность блокировать движение.
* Гибкость добавления новых типов объектов с уникальной логикой.

## Точки интеграции в текущем коде

| Пункт | Где |
| --- | --- |
| `get_rect()` | Присутствует для `Entity`, `Obstacle` (`Food` наследует от `Entity`) |
| `World.handle_collisions()` | В `engine/world.py`, вызывается из `World.update(dt)` после движения |
| `on_collision()` | Пустой метод в `Entity`, переопределяется в подклассах (`Food`, `Obstacle`) |
| `blocks_movement` | Флаг на уровне класса в `Entity` (`False`); `True` для `Obstacle` |
| `revert_position()` | В `Entity` — восстанавливает `x`/`y` из снимка `save_position()` |
| `skip_collision_check()` | В `Entity` — возвращает `False`; эффекты могут переопределить на `True` |
